# Xbox Underground 2: проверенная последовательность DDAY (итерация 20)

Источники: оригинальный пользовательский NTSC-U `default.xbe`, SHA-256
`c8cab1bfe7cf26553e84eb4ef2a26d16f6b06260f7494c583802bc00fd81dd31`.
Анализ **статический**, адреса относятся к виртуальному пространству **x86 Xbox**.
Бинарник EA и полученный из него код в репозиторий не добавлены.

## 1. Входная цепочка

Подтверждённые прямые вызовы:

```
0x000B3650  проверки глобальных объектов и параметра результата
  0x000B3680 -> 0x000B3490
    0x000B34B7 -> 0x001596F0  обработка события
      0x0015976D -> 0x00110A00  проверка одного из условий
      если проверка истинна:
        0x0015979B -> 0x0014D6C0  учёт результата/статистика
        если текущий ID == DDAY_EVENT_B:
          0x001597BA: this->active_event = NULL
      затем (в ОБОИХ вариантах результата проверки):
        если текущий ID == DDAY_EVENT_A:
          0x001597ED -> 0x00110880  найти DDAY_EVENT_B
          0x001597F8 -> 0x0014D320  активировать B
```

Принципиальный факт: переход `0x159774 je 0x1597C4` при
отрицательном `0x110A00` обходит `0x14D6C0`, но **не**
проверку активного ID A, находящуюся после `0x1597C4`.
Таким образом, для **A→B не обязательно положительное значение
именно этой дополнительной проверки**. Вызов всего обработчика
`0x1596F0` с действительным результатом игрового события по-прежнему
обязателен; обычный проезд `Paths4000` не заменяет его.

## 2. Структуры и действия

- `0x00110880` ищет хеш ID в таблице с шагом **0x88 байт**,
  сравнивая `record+0x08`. Длина соответствует оригинальным
  PC/Xbox CareerManager race-записям. Отдаёт запись или null.
- `0x00110A00` просматривает дочерние элементы активной записи:
  количество из `event+0x35`, начало `event+0x38`, шаг 8 байт.
  Проверяется **тип элемента 4** и совпадение его хеша с
  `result+0x38`. Тип 4 пока нельзя называть «победой».
- `0x0014D320` сохраняет указатель активной записи в
  `this+0x8738` и вызывает дополнительные процедуры её инициализации.
- `0x0014D6C0` обновляет статистику/учёт и может использовать
  `this+0x7134` для денежных изменений, но соответствующая ветвь
  зависит от дополнительных флагов `this+0xD26/D27`.
  Нет оснований назначать DDAY обычный денежный приз.
- `0x0013F8C0` сравнивает входной хеш с активным ID и вызывает
  `0x136540`/`0x1365C0` после проверок. Их семантика требует
  дополнительных исследований; «успешный финиш» **не доказан**.

## 3. Отдельный восьмисостояний автомат

`0x0015E69F -> 0x00140DE0`; jump-table по `0x00141020`:

| State | Xbox handler | Результат видимой ветви |
|---:|---|---|
| 1 | `0x140DFA` | Запоминает момент и назначает 2 |
| 2 | `0x140E20` | При истечении времени назначает 3 |
| 3 | `0x140E53` | При проверке подсистемы назначает 5 |
| 4 | `0x140EB9` | При времени и проверке назначает 5 |
| 5 | `0x140EF9` | После таймера, проверки и двух флагов — 6 |
| 6 | `0x140F61` | При успешных проверках — 7, вызывает `0x13F8C0(A)` |
| 7 | `0x140FD6` | Назначает 8 |
| 8 | `0x141012` | Через `0x140D50` ставит состояние 9 и вызывает обработку A |

Состояния — не уровни карьеры. Процедура работает с глобальным
таймером `0x428A00`, объектом `0x406AAC`, флагами и отдельным
режимом мира. Она не доказывает координаты автосалона.

## 4. Практический вывод для H700 OpenUG2

**Не вводить сейчас авторазблокировку DDAY B по маршруту, таймеру или
показу `SCENE05`.** Сохраняем действующий защищённый механизм
`ug2_prologue_record_verified_finish()`, пока не будет установлен
достоверный источник реального окончания scripted-события.

Ближайшие цели исследования:
- Проследить источники результата на `0x000B3650`, в том числе
  `0x111080`, глобалы `0x406934/0x40693C`.
- Проверить смысл подзаписи типа 4 и `0x132730`, условия машины
  вступления и возможные триггеры мира.
- Найти запись/чтение состояния кампании и флагов A/B в профиль.
- Восстановить координаты и размеры shop-триггера из реальных world
  ресурсов, а не по одному хешу.

## 5. Репродуцируемая проверка

```sh
python3 tools/ug2_xbe_dday_flow_probe.py /path/to/default.xbe --json
```

Новый скрипт (только чтение) проверяет оригинальную версию по SHA-256,
9 точных `CALL rel32`, таблицу 8 адресов и 6 машинных сигнатур.
Не работает с произвольной неподтверждённой ревизией XBE и не запускает
игру. Проверка выполнена на переданном `default.xbe`, все тестовые
якоря совпали. На физической Anbernic проверка не выполнялась.
