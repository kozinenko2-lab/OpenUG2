# Итерация 18: поиск ссылок на оригинальные триггеры без реконструкции координат

## Задача

В оригинальном `GlobalB.lzc` подтверждены записи `CC_CAR_LOT_1`
(открытый на нулевом этапе автосалон, `CARLOT01.BIN`, `SCENE05`)
и `CRIB_1` (`CRIB01.BIN`, `SCENE06`, требуется завершение
`DDAY_EVENT_A`). В этих записях **нет проверенных X/Y/Z и объёма
триггера**. Поскольку один путь `Paths4000` участвует в обеих
нулекруговых событиях DDAY, просто проверить номер маршрута также
недостаточно.

Для поиска ссылок в других игровых ресурсах добавлен ограниченный
read-only C-инструмент `tools/ug2_trigger_probe.c`.

## Использование

Собрать нативный бинарник на Linux/ARM64:

```sh
make ug2-trigger-probe
./build/ug2_trigger_probe /path/to/original/NFSU2 --max-mib 512 \
    > ./OpenUG2_TriggerAudit.log
```

Для теста парсера без коммерческих ресурсов:

```sh
make ug2-trigger-probe-test
```

На PortMaster скопировать скомпилированный `ug2_trigger_probe`
рядом с `nfsu2` и включить в верхней части `OpenUG2.sh`:

```bash
TRIGGER_AUDIT="1"
TRIGGER_AUDIT_MAX_MIB="512"
```

На запуске появится отдельный файл
`openug2/logs/OpenUG2_TriggerAudit.log` в папке игры.
**Вернуть `TRIGGER_AUDIT="0"` после одного аудита**, чтобы не
замедлять каждое открытие игры. По умолчанию он выключен.

## Что ищет и что означает результат

Сканер обходит только регулярные файлы с расширениями
`.BUN`, `.BIN`, `.LZC`, `.DAT` в исходных
`TRACKS/`, `GLOBAL/`, `FRONTEND/`. Символические ссылки не
разыменовываются. Совпадения выдаются как
`file=… offset=… encoding=LE32|ASCII identity=…`.
В рабочей памяти используется ~64 KiB буфер чтения; у сканирования
есть лимит 32–4096 MiB (по умолчанию 512 MiB), 10 000 файлов,
128 совпадений и максимум 9 уровней директорий.

Точные исходные значения:

| Исходное поле | Значение |
|---|---|
| `CC_CAR_LOT_1` триггер (BinHash(`TRIGGER_CC_CAR_LOT_1`)) | `0xFFCC6A4B` |
| `CRIB_1` поле trigger (значение пока не расшифровано) | `0xF98D0C92` |
| `DDAY_EVENT_A` | `0xDD60E402` |
| `DDAY_EVENT_B` | `0xDD60E403` |
| `CC_CAR_LOT_1` raw name key (+0x38) | `0xEC17E618` |
| `CRIB_1` name hash | `0x55446B8F` |

Также проверяется наличие обычных ASCII-строк
`TRIGGER_CC_CAR_LOT_1`, `CC_CAR_LOT_1`, `CRIB_1`.

**Совпадение — только ссылка в потоке данных, а не координаты
триггера, его объём, обработчик, вызов ролика или завершение сценария.**
Отсутствие совпадений также не является доказательством отсутствия
события: инструмент **не распаковывает сжатые блоки**, и часть ссылок
может находиться в коде оригинального исполняемого файла.

`complete=no` означает, что лимит достигнут или произошла ошибка.
Частичный анализ не используется как свидетельство отсутствия ссылки.

## Проверки

Синтетический тест проверяет 4-байтовый LE-хеш, разбитый границей
64 KiB, ложную big-endian последовательность, ASCII токены,
поиск в нескольких исходных каталогах, пропуск симлинков и
корректное обозначение неполного результата. Добавлен тест и бинарник
в ARM64 CI; реальная физическая Mali H700-консоль ещё не тестировалась.

Следующий шаг после появления кандидата на конкретный `BUN/BIN`:
декодировать окружающий *оригинальный* тип записи и проверить
топологию/геометрию, а не переносить четыре совпавших байта как
игровые координаты. Нельзя записывать DDAY-завершение без отдельной
подтверждённой игровой логики.
