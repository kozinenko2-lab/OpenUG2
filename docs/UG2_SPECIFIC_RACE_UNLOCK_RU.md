# OpenUG2: зависимости SPECIFIC_RACE_WON (итерация 15)

## Задача

В оригинальном PC `GlobalB.lzc` гонка первого этапа
`STAGE_1_CIRCUIT_1` (маршрут 4013, 3 круга, 3 соперника, 250)
имеет способ разблокировки `SPECIFIC_RACE_WON` (значение 0).
Поле `GCareerRace +0x10` при этом является **32-битным хешем имени
предыдущего события**, а не набором четырёх независимых требований.
Подтверждённый в оригинале хеш `0xdd60e403` соответствует
`DDAY_EVENT_B`.

## Изменения

- `ug2_career_prerequisite()` ищет **одного** предшественника по хешу
  оригинального `GCareerRace.id` в загруженном `GlobalB.lzc`.
  Отсутствующий, дублированный или коллидирующий ID блокирует гонку.
- `ug2_career_resolve_circuit_for_profile()` проверяет, что в
  текущем `Career` уже имеется подтверждённый выигрыш
  `career_has_win(profile, "UG2_ORIGINAL", predecessor->id, CAREER_WORLD)`.
  Голый `--career-race`, отметка наличия маршрута или запись другого
  домена не открывают зависимое событие.
- И предгоночное вооружение AI-кольца, и финишная транзакция используют
  **одинаковую profile-aware проверку**. Вариант без профиля оставлен для
  обратной совместимости; для SPECIFIC_RACE_WON он намеренно закрыт.
- Старые сохранения не преобразуются, исходный `GlobalB.lzc` не меняется.
  Текущая транзакция награды сохраняет копию состояния до публикации
  выигрыша в память: при ошибке файловой системы награда не выдаётся.

## Проверки

```sh
make ug2-career-binding-test
make ug2-career-credit-test
```

Синтетические тесты без оригинальных ресурсов проверяют отсутствие
предшествующей победы, чужой домен сохранения, настоящий ID, ошибку
сохранения, загрузку после сохранения и защиту от повторной выплаты.
ARM64/GLES2 GitHub Actions на Ubuntu проверяет сборку и эти тесты,
но не эмулирует RG40XX H/Mali.

## ВАЖНО: что ещё не сделано

Это **не** означает, что первый этап уже проходим на консоли.
Пока игра **не реализует фактическое прохождение `DDAY_EVENT_B`**
как доказанный оригинальный сценарий с фиксацией результата; поэтому
чистое сохранение первого запуска продолжает блокировать
`STAGE_1_CIRCUIT_1`. Тест вручную создаёт синтетическую подтверждённую
победу, но продуктовый код не подставляет такую запись и не начисляет
денег без события.

Следующая задача: определить параметры, маршрут/триггеры и истинный
критерий прохождения `DDAY_EVENT_B` из пользовательского оригинала,
привязать к игровому финишу и атомарно сохранить его canonical ID.
Не подменять победу фактом посещения маркера, запуском гонки или
консольным ключом `--career-race`. Затем реализовать реальные
переходы этапов и остальные четыре типа условий; типы 2, 3 и 4
пока намеренно закрыты.

Этот порт — независимый проект, а не перепаковка оригинального EXE.
Авторские бинарные ресурсы EA не включаются в GitHub.
