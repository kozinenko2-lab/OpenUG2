# Связь оригинальных карьерных гонок, маршрутов и выплат

Реализация начата поверх чистой ветки `portmaster/ug2-original-career`.
Источник форматов — [NFSTools/GlobalLib](https://github.com/NFSTools/GlobalLib)
(MIT). Библиотека содержит полноценную C# систему чтения/записи
`CareerManager`, но для **H700/1 ГБ/PortMaster** мы переносим только
необходимую модель **в C99**, без встроенного .NET-редактора и без EA-ресурсов.

## Проверенная связь с игрой

В оригинальном `GLOBAL/GlobalB.lzc` `GCareerRace.TrackID_Stage1`
является числом из настоящего `TRACKS/ROUTES<REG>/Paths<NNNN>.bin`.
То же число имеется в `world.city.ev[i].id` и используется
`world_race_start()`. Поэтому теперь можно связывать настоящую гонку
с маршрутом, не угадывая имена.

Но `Paths4201` используется и `STAGE_1_DRAG_1`, и `S3_DRAG_4`,
и `S3_SPON_DRAG_6`, и `S4_DRAG_11`. **Один маршрут не равен одной
карьерной гонке.** Новая функция `ug2_career_select()` разрешает
событие по оригинальному *имени + этапу*; `ug2_career_unique_route()`
находит событие по карте только если уникально для текущего этапа.
При дубликатах нужен точный ID, иначе выплаты нет.

`--career-race STAGE_1_CIRCUIT_1` находит исходную гонку
в `GlobalB.lzc`, проверяет этап сохранения и вычисляет
`--event 4001` автоматически (если он доступен в выбранном районе).
`--event 4201` без ID на этапе 3 может быть неоднозначен
и не начисляет деньги.

## Условия честной награды

`ug2_career_award()` требует *всё одновременно*:

- исходная гонка относится к сохранённому этапу;
- точный ID маршрута соответствует выбранному исходному событию;
- `world.city.race.finished` после всех авторских контрольных точек;
- реальная гонка с AI завершена на **первом месте**;
- число фактических AI соперников не меньше исходного `NumOpponents`;
- ID гонки не был учтён в сохранении ранее.

Значение `CashValue` берётся из оригинального файла вместо
временных 500 единиц. Повторная победа не добавляет деньги.
**Важно:** движок пока не связывает все маршруты `world_race_start()`
с завершением полноценной гонки против AI; многие sprint/drag/drift
будут проходить только в режиме контрольных точек и не смогут получить
награду, пока не появится достоверная система финиша их соперников.
Никакой фиктивной выплаты за одиночный проезд нет.

Оригинальные `GCareerStage` unlock-правила ещё требуют реализации.
В новой ветке автоматическое продвижение по временным условиям
отключено при начислении проверенной награды.

## Локальные модификации без перепаковки архивов

В отличие от больших ПК-редакторов, для быстрой настройки экономики
на RG40XX H реализован маленький безопасный **оверлей** над загруженным
оригинальным каталогом — `--career-mod`. Пример содержимого
`mods/career_cash.txt` внутри папки игры:

```ini
# Мои локальные изменения денежных наград, НЕ в исходном файле EA
STAGE_1_CIRCUIT_1 = 500
S3_SPRINT_6 = 750
```

Запуск (путь к игре и сохранению выбирает пользователь):

```sh
./nfsu2 /mnt/sdcard/ports/openug2/game \
  --career-save /mnt/sdcard/ports/openug2/saves/career.dat \
  --career-race STAGE_1_CIRCUIT_1 \
  --career-mod /mnt/sdcard/ports/openug2/mods/career_cash.txt \
  --track STREAML4RA --hud
```

Если указанное оригинальное событие отсутствует, значение недопустимо
или одна запись продублирована, вся модификация отклоняется атомарно.
Редактирование не изменяет `GlobalB.lzc`, каталог в GitHub или
оригинальные файлы PC-игры. Изменённый баланс хранится только в
отдельном сохранении OpenUG2. Для восстановления оригинальной экономики
достаточно не указывать `--career-mod`.

**Рамки проекта:** MIT разрешает использование кода GlobalLib с
сохранением copyright, однако наш порт не встроил GUI/C#/.NET программу
и не копирует базы EA. Встроенный редактор машин/магазинов —
следующий отдельный этап после подтверждения парсера их полей.

## Тестирование

```sh
make ug2-career-file-test
make career-event-bridge-test
make career-mods-test
```

Синтетические тесты проверяют коллизии одного маршрута между
спонсорами/этапами, отказ в оплате за одиночный финиш/проигрыш,
защиту от повторной выплаты, ошибки оверлея и неизменность каталога
при недопустимых данных. GitHub Actions также собирает ARM64 GLES2.
Полноценное прохождение на реальном H700 пока не подтверждено.
